# 量測任務紀錄

任務以 `<repo>` 為基準，採用 `<repo>/.agent_state/measurement-tasks/<task-id>/`。既有任務沿用已確認的位置，不在每次 session 新建副本。

## 建立與更新

最小紀錄是 INDEX.md 與 journal.md。INDEX 表示當前狀態；journal 保留重要判斷轉折。正式數據與圖像引用既有 artifact，不把完整工具輸出搬進文件。

新任務的 INDEX 可以從以下標題開始，不需要額外 metadata 格式或產生器：

```markdown
# 任務名稱
## 目標與有效 policy
## 戰略階段
## 已知證據與目前物理圖像
## 當前戰術目標與下一步
## 執行中操作與待確認結果
## 預算與待使用者決定事項
## 資料、經驗與決策入口
```

目標與 policy 保留使用者原話及條件。摘要不能擴張授權。被替換的決定留在 journal，INDEX 只指向目前有效版本。使用者修正要能區分本次例外、可重用經驗與長期 policy。

證據入口指出數據及分析產物位置。工作假說與直接觀察分開。階段完成需要什麼證據、目前哪些未知會影響下一步，也在 INDEX 說清楚。主動確認的預算、估算依據及剩餘額度留在 INDEX；未知成本要標明，不能視為無上限，也不強求虛構數字。

完成條件是接手者能從 INDEX 找到下一步與必要依據，而不用掃描整段對話或所有檔案。

## Journal 寫什麼

用帶時間的短段落記錄重要觀察、候選解釋、考慮過的選項、選擇理由、結果與改道。保留行不通路線的條件和原因，避免下一個 session 重複同一嘗試。

常規工具讀取與沒有新資訊的重跑不需要逐筆記錄。分析腳本、圖表或較長推導需要保留時，存成任務內的檔案並從 journal 引用。

## 何時持久化

- 目標、policy、戰略或重要工作假說改變時。
- 啟動長時間或高成本操作前，記下意圖；取得回覆後補上當時 session、操作與 tab 等可用識別，以及預期產物。
- 一輪結果改變下一步選擇時。
- 求助、使用者接手、暫停、交接或結束時。

使用者中斷量測時，INDEX 記錄停止位置、待確認結果與等待使用者說明，不把下一步寫成自動重試。接手 session 也須保留這個暫停狀態，不能因為重新連線就恢復執行。

這些更新不依賴可預知的壓縮通知。任務檔案不隨 session 結束清除。

## 恢復與交接

1. 讀目前生效的測量 skill、任務 INDEX，以及它指向的必要 policy／決策原文。不要只靠對話壓縮摘要推斷授權。
2. 核對 GUI 所連環境、context、tab、執行中操作與實際已保存的產物。Session handle 是上次觀察的線索，不是跨 session 可直接使用的永久 ID。
3. 比較文件與現況。操作可能已完成、仍在執行、失敗，或在回覆前中斷。查清楚後更新 INDEX；無法確認時保留未知，不盲目重送。
4. 使用者已改變設定時，確認原假說及下一步是否仍適用。必要時重新規劃，不能自動恢復舊設定。
5. 只有目前決策需要時才展開 journal、經驗、圖像與資料。不為恢復而讀完整歷史。

恢復完成條件是已核對有效授權、當前狀態與下一個動作，並知道哪些舊觀察已失效。若 INDEX 無法提供下一步，先修補紀錄或向使用者確認。

## 圖像、資料與結案

MCP 回傳的圖像可能是 session 暫存，server 關閉後會消失。要支援交接的圖應另存至允許的持久位置並記錄來源；長期教學圖可在形成經驗時精選加入 measure_knowledge。

保存意圖、操作完成與 artifact 寫入成功是不同事實，依實際狀態記錄。結案不刪除仍需追溯的紀錄，也不自動停止未知的 live operation。保留期限與歸檔按使用者的工作專案規則處理。
