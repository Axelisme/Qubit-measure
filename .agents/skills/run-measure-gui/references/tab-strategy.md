# Tab 生命週期

## 新建或重用

同一 adapter 連續調參或重複量測時，明確傳 `reuse_tab_id`。需要並排比較、改用不同 adapter，或刻意保留獨立工作頁時才新建。未傳 `reuse_tab_id` 會新建，recipe 不自動選 tab。

重用前讀 tab 現況，確認沒有仍在執行的操作。核對上一個 Run 的 raw 與本次判斷需要的分析、圖片或 writeback 證據已保存，並記錄實際路徑。Recipe 會 reset；重新傳入要維持的設定，不能假設舊 cfg overrides 或分析選項會延續。

同名 canonical 圖片可能被後一次分析覆寫，不是歷史備份。需要比較舊模型或舊結果時，先依保存契約保留可辨識的證據，再 reset。

## 保存不完整

Terminal execution 只代表流程結束。逐項核對保存回覆的 artifact、實際路徑、錯誤與未知狀態。

Raw 或必要分析證據尚未保存時，先補保存；無法完成時保留 tab，記錄缺口並求助。完成這個核對前不 reset 或 close，也不因逾時自動重送 recipe。重新分析同一 Run 時，保留對照所需的舊圖與分析設定。

## 使用者的 tab 與清理

使用者擁有的 tab 預設保留。需要操作它時先核對當次授權，不把它當成 agent 的空白工作頁。

清理只透過明確的 `tab_close`。關閉前確認 target、操作是否仍在執行、保存是否完整，以及授權是否涵蓋關閉；未保存內容的 discard 需要明確授權。缺少條件時保留 tab，說明下一步。

任務結束按比較用途與當次授權保留或關閉 agent 的 tab，不設定全域 tab 數量上限，也不順便關閉使用者的 tab。

## 沿用值驗證

`cloned_from` 表示從其他工作點或條目複製，不能當成本工作點的新校準。在使用前至少快速驗證一次，並記錄來源、驗證條件與結果。

驗證要回答該值是否仍適用。頻率可先做授權內的短掃描；pulse 候選可用 Rabi 的週期與第一個峰核對；讀出參數要核對當前資料與讀出條件。這些是選項，不是每個值都必跑的固定流程。

沒有足夠證據時保留「沿用、尚未驗證」，暫停依賴它的操作或求助。既有 offline 證據若不足以回答當前適用性，不把它當成完成驗證。需要新的硬體或資料操作時先取得授權，不能藉驗證擴張當次 policy。

驗證通過後才據證據選擇使用或 accept。Accept 前仍要核對全部候選及目的地；驗證一個值不等於批准所有 writeback。
