# 使用與維護量測知識

知識入口是 `<repo>/measure_knowledge/`，由自身獨立 Git repo 管理。使用者可以用 symlink 讓不同 repo 共用；agent 不建立、改向或修復共享連結。

## 核對與初始化入口

首次使用或換 repo 時，先確認入口。不要因為是開發主機就啟動 GUI 或連線儀器，初始化只需要本機檔案與 Git。

- 已有目錄或有效 symlink：確認 `git -C <knowledge> rev-parse --show-toplevel` 的實體路徑正是知識目錄的實體路徑。Git 若向上找到外層 repo，不能當成初始化成功。確認 README.md 與 routing.md 可讀，沿用現有內容，不重套模板。
- 失效 symlink、一般檔案、非獨立 Git 目錄或入口文件缺失：回報具體狀態，保留內容，停止該初始化或修復動作。
- 路徑確實不存在，包含不是失效 symlink：按下面步驟建立。不猜測使用者的共享位置。

建立步驟：

1. 確認外層 Git 已忽略根入口，例如 `git -C <repo> check-ignore -- measure_knowledge`。若未忽略，先回報規則缺口，不在量測中自行修改程式碼 repo 的設定。
2. 使用不帶 `-p` 的 mkdir 建立目標，讓已有路徑的競爭修改直接失敗。從本 skill 的 [README 模板](../templates/knowledge/README.md) 與 [routing 模板](../templates/knowledge/routing.md) 複製兩份入口到新目錄，不覆寫現有檔案。相對模板路徑以本文件解析，不以 cwd 解析。
3. 在該目錄執行 `git init --initial-branch=main`，再確認 Git top-level 與實體知識目錄一致。不要在外層執行 git init，也不建立 remote。
4. 只 stage 新建立的 README.md 與 routing.md，檢查 diff，作一個本機初始 commit。沿用既有 Git identity；若尚未設定，回報並請使用者提供，不捏造作者或修改全域設定。
5. 確認知識庫自身狀態乾淨、入口可讀、外層仍忽略知識庫。第一條經驗出現時才建立 experiences 子目錄，不填入虛構案例。

中途失敗保留已建立內容並回報完成到哪一步，不刪除目錄重跑。下次應將它視為未完成初始化，不偽裝成全新缺失路徑。不同 agent 未安排寫入順序時，不同時初始化同一入口。

## 選擇查找入口

- 已知相關條目時直接讀它的 README。
- 有症狀、參數名或實驗名稱時，用原生搜尋在知識目錄內查找。結構欄位也可以作搜尋線索。
- 不確定該查什麼時，先讀知識庫入口和 routing，再進入相關 domain。

從目前的判斷問題出發，不要求先猜對原因。查閱正常表現與品質依據，也查反例和限制。只展開需要的方法、案例、圖片或腳本，不一次讀完整資料夾或整座庫。

匹配到的文字只是候選知識。核對實驗條件、環境差異與未確認部分。曾在某 qubit 觀察到不等於僅適用於它，描述相似也不等於原因相同。

遇到互相衝突的經驗，保留差異並選擇能區分的證據。找不到適用內容時標示缺口，使用當前證據作暫定判斷，不把搜尋不到當成物理上不存在。

初始化受阻時回報；沒有可用經驗時不宣稱已查閱。是否繼續不依賴經驗庫的工作，依當次目標與 policy 判斷。

完成條件是知道目前選用的方法為何適用、尚有哪些限制，或已清楚記錄沒有足夠知識可用。

## 一條經驗放什麼

一個資料夾處理一個可獨立使用的判斷問題。README 說明用途、適用條件、核心方法、限制，以及何時看其他文件。

正文可記錄正常特徵、合理變異、物理圖像、候選原因、辨別實驗、接受／停止／求助依據與成本取捨。不強制每條填滿同一表格。

分開保留已觀察的環境、推測適用條件、已知反例與未知範圍。環境變動後重新核對適用性，不能因為曾經成功就照做。

圖片附上來源、已知條件、該看哪裡、能支持什麼及不能支持什麼。文字要足以讓搜尋找到圖例。不要只連到 MCP session 暫存檔，也不要把圖像外觀當成通用門檻。

可重用的離線腳本說明輸入格式、環境、輸出與副作用。使用前讀懂入口與相關內容，確認在當次授權內；不因為位於知識庫就視為已獲執行授權。保留資料來源，不覆寫原始量測檔。

## 何時修訂

新辨別方法、反例、適用限制、推翻原解釋的結果或專家修正，才值得長期沉澱。普通量測值和任務進度仍留在正式資料與任務紀錄。

新增前搜尋既有條目。相同判斷問題優先整合，不為每次案例另造一條幾乎相同的經驗。粒度變大而開始服務不同問題時，再拆分。

Agent 可自主修訂方法，說明新證據改變了什麼。區分觀察、解釋及驗證。使用者提供的專家判斷可作依據，但不標成實驗證實。多次引用也不等於多份獨立證據。

目前仍有判斷價值的反例與限制留在現行內容；淘汰的措辭交給 Git history。不能透過修改驗收方法降低當次目標或擴張 policy。

修改後確認合理的 routing 入口能找到它。Routing 只保存進入條件與連結，不複製正文。同一條目可有多個入口；先使用既有 domain，必要時才調整分類。

## 使用 Git

修改前確認操作目標是知識庫自己的 Git repo，而不是向上解析到外層程式碼 repo。查看既有變更，保留其他人的工作。共享 symlink 不提供寫入隔離，未確認協作安排時不併發修改同一內容。

一次提交整理一項有意義的知識變更，包含必要的正文、案例與 routing 更新。提交前讀 diff，檢查是否誤刪限制、加入錯誤來源或混入無關變更。不要替使用者提交其他未授權的修改。

需要追溯時讀 log／diff。需要撤銷時確認後續依賴，使用新的修訂或 revert 保留歷史，不用整庫 reset 丟棄後續工作。遠端 push 依使用者授權，不因本機 commit 而自動執行。

完成條件是修訂理由與依據可追溯、現行內容可搜尋、引用有效，且 Git 變更只包含本次知識工作。重要修訂可彙整通知使用者，不要求逐筆批准。
