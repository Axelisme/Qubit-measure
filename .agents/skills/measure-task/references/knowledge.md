# Knowledge

**讀者：** agent。開始或恢復任務時核對知識入口；判讀結果與結案沉澱時，依本頁查找及修訂可重用經驗。

知識入口是 `<repo>/measure_knowledge/`，下文以 `<knowledge>` 表示，由自身獨立 Git repo 管理。共享 symlink 由使用者建立、改向與修復，agent 保留既有連結。共享入口的寫入順序須另行安排。

## 核對入口

首次使用或換 repo 時，先以本機檔案與 Git 確認入口。

- 已有目錄或有效 symlink：核對 `git -C <knowledge> rev-parse --show-toplevel` 的實體路徑，須正是知識目錄的實體路徑。向上找到外層 repo 代表入口尚未通過核對。確認 README.md 與 routing.md 可讀，沿用現有內容。
- 失效 symlink、一般檔案、非獨立 Git 目錄或入口文件缺失：回報具體狀態，保留內容，停止該初始化或修復動作。
- 路徑確實不存在，且已排除失效 symlink：依下一節建立本機知識庫。共享位置由使用者指定。

完成條件：入口是可讀的獨立知識庫、已確認可以新建，或已回報具體阻礙。入口受阻時，是否繼續不依賴知識庫的工作，依當次目標與 policy 判斷。

## 初始化缺失入口

初始化只操作本機檔案與 Git。多個 agent 使用同一入口時，先安排單一寫入者。

1. 確認外層 Git 已忽略根入口，例如 `git -C <repo> check-ignore -- measure_knowledge`。規則缺失時回報，程式碼 repo 的設定修改另取授權。
   完成條件：外層確實忽略根入口，否則停在規則缺口。
2. 使用不帶 `-p` 的 `mkdir` 建立目標，讓已有路徑的競爭修改直接失敗。從 [templates/knowledge/README.md](../templates/knowledge/README.md) 與 [templates/knowledge/routing.md](../templates/knowledge/routing.md) 複製入口到新目錄，使用遇到既有檔案即失敗的方式。模板路徑相對於本文件解析。
   完成條件：只有新建目錄收到兩份入口，既有檔案保持原樣。
3. 在知識目錄執行 `git init --initial-branch=main`，核對 Git top-level 與實體知識目錄一致。本機初始化止於獨立 repo，保留未設定 remote 的狀態。
   完成條件：Git 管理的是知識庫自身，而非外層 repo。
4. 只 stage 新建的 README.md 與 routing.md，檢查 diff，作本機初始 commit。沿用既有 Git identity；缺失時請使用者提供，作者與全域設定保持原樣。
   完成條件：初始 commit 只含兩份入口，或已回報 identity／提交阻礙。
5. 確認知識庫狀態乾淨、入口可讀、外層仍忽略知識庫。第一條實際經驗出現時才建立 `experiences/`。
   完成條件：三項核對都通過，知識庫可供查找與修訂。

中途失敗時保留已建立內容，回報停在哪一步。下次把它視為未完成初始化，先核對現況及修復授權。

## 查找與適用性

判讀或沉澱前，讀 `<knowledge>/README.md` 的現行索引與維護規則。依目前問題逐步展開：

1. 實驗名稱：從主索引找相關實驗，裁定結果時優先找 `judge` 條目；選擇路線時找 `route`，離線整合分析找 `analysis`。
   完成條件：已定位候選條目，或已記主索引的缺口。
2. 症狀：再以目前症狀查 `<knowledge>/routing.md`，補上其他候選原因、正常變異與辨別方法。
   完成條件：已核對相關症狀入口，或已記 routing 的缺口。
3. 搜尋：索引仍不足時，在知識目錄內以實驗名稱、症狀、參數或 frontmatter 欄位作 `grep`／原生搜尋。
   完成條件：找到可用條目，或明確記錄沒有足夠知識可用。

按問題只讀相關 README，再依其 pointer 展開需要的方法、案例、圖像或腳本。匹配文字只是候選，須核對實驗條件、環境差異、scope、限制與反例。某 qubit 的案例是觀察來源，適用範圍另由證據判斷。

衝突的經驗保留差異，選能區分它們的證據。查無條目時以當前證據作暫定判斷，把知識缺口記入 round；搜尋不到只代表目前缺少依據。

查找完成條件：round 記下實際採用的條目、適用理由與限制，或明確記缺口。入口不可用時，照實回報查閱範圍。

## 沉澱與 kind

新辨別方法、反例、適用限制、推翻原解釋的結果或專家修正，才寫入可重用經驗。普通量測值與任務進度留在正式資料與 round。

新增前搜尋相同判斷問題，優先修訂既有條目。一個經驗資料夾處理一個可獨立使用的問題，以 README.md 為入口，按用途選 kind：

| kind | 處理的問題 |
| --- | --- |
| `route` | 目標加現況如何選下一個實驗，何時回頭、何時停。 |
| `judge` | 某實驗的判讀與驗收，正文骨架見下文。 |
| `analysis` | 離線整合分析的方法、判讀與驗收。 |

`judge` 正文依問題寫正常樣貌、症狀與候選原因、辨別動作、接受／重做／求助、限制與反例、案例。其他 kind 也須交代適用條件、方法與限制；獨立判斷問題增多時再拆條目。

每個條目 README 的 frontmatter 填四欄。填寫格式與檢查細節依 `<knowledge>/README.md` 的現行規則。

| 欄位 | 意義 |
| --- | --- |
| `kind` | `route`、`judge` 或 `analysis`。 |
| `experiments` | 實驗名稱列表，供主索引查找。 |
| `symptoms` | 症狀列表，供 routing 查找。 |
| `scope` | `sim`、`real` 或 `both`，表明條目的適用範圍。 |

正文分開保留直接觀察、分析解釋與驗證，交代已觀察環境、推測適用條件、反例及未知。專家判斷標明來源與性質，獨立實驗證據另列。修訂時保留仍有判斷價值的限制，淘汰措辭交由 Git history 追溯；當次驗收與授權仍以地圖的有效 policy 為準。

案例保存精選圖與來源清單，包含 run id、路徑及已知條件。圖說指出該看哪裡、支持什麼及限制。正式資料留在 artifact 儲存位置，知識庫引用來源，以精選圖例取代 JSON 全量副本或 MCP session 暫存連結。

離線腳本記輸入格式、環境、輸出與副作用。執行前讀入口及相關內容，核對當次授權，保留原始資料。模擬案例只支持判斷方法與反例；套用真實硬體前另核對單位、功率、時序、phase convention、模型及安全限制。

沉澱完成條件：每項修訂都有可重用的問題、kind、四欄及證據來源，限制可辨認；主索引與症狀 routing 都能從適用問題找到它。索引只放進入條件與連結，正文維護一份。

## 本機提交

修改前核對知識庫自身的 Git top-level 與既有變更，保留其他人的工作，確認共享入口的協作安排。修訂後讀 diff，只 stage 本次授權的正文、案例與索引更新，一項有意義的知識變更作一個本機 commit。此次流程不 push。

需要追溯時讀 log／diff；撤銷前確認後續依賴，以新修訂或 revert 保留歷史。重要修訂可彙整通知使用者。

完成條件：修訂理由與依據可追溯，索引可找到現行內容，引用有效，commit 只含本次知識工作。沒有值得新增的經驗時，在結案 round 記明即可。
