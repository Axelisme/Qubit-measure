# Analysis

**讀者：** agent。輸入是既有資料、任務要裁定分析結果時，依本頁調整地圖與 round。

沿用 [Measure task](../SKILL.md) 的流程。本頁只列純分析任務的差異。

## 地圖與輸入

- 純分析任務省略硬體、GUI 與設備占用預算欄位。保留適用的時間、運算與金錢成本，以及限制投入的條件。
- 「資料與經驗入口」記既有資料的來源、run id 或其他可辨識版本、保存位置與已知條件。分析入口記腳本或方法、輸入格式、參數及衍生產物位置。
- 驗收階梯寫分析結果須支持哪個決定，以及可信度所需的證據。例子是「同一組資料的候選模型已比較，結論對資料篩選的敏感性有依據」。
- 「執行中操作與待確認結果」記分析工作與產物狀態。恢復時核對輸入是否改變、分析入口與參數是否仍適用，以及預期產物是否實際保存。

完成條件：地圖能定位可用的既有資料與分析入口，並指出分析要達成的接受狀態。輸入變動造成的失效觀察已標明。

## Round 與裁定

- 候選動作比較重做分析、換方法、取得缺失背景或求助的資訊與成本。需要新量測時，先確認涵蓋該工作的有效授權，再依量測分支處理。
- 執行紀錄以資料來源、方法、參數與產物引用取代 GUI 操作識別。來源資料保持原樣，衍生輸出另存。
- 「物理圖像」填分析解釋及可信度限制。分開寫資料直接支持的結果、模型假設與外推範圍。
- 裁定對象是分析結果的可信度。核對單位、資料選取、方法假設、誤差或敏感性，以及競爭解釋。依問題查用 `analysis` 條目及相關實驗的 `judge` 條目。
- 沿用 [Round 的裁定](round.md#裁定)，註明接受哪個分析結論，或重做、改道、求助要補什麼證據。分析可信與完成任務驗收分開判斷。

完成條件：round 能由輸入、方法及產物追溯到可信度判斷，並交代結論限制與下一步。需要新增量測的缺口已留在地圖。
