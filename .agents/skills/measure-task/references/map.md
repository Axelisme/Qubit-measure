# Map

**讀者：** agent。建立、更新或恢復任務 INDEX 時，用這份地圖模板保存目前有效狀態與下一步入口。

## 地圖的邊界

`<task-dir>/INDEX.md` 是目前狀態，`rounds/NN-<slug>.md` 是每輪判斷。地圖指向支持當前判斷的 round，歷史轉折由 [Round](round.md) 承接。正式數據、圖像與長推導引用 artifact，文件只留判斷所需摘要。

目標與 policy 保留使用者原話、來源及適用條件。摘要的授權範圍以原文為限。替換決定時，把舊版本與替換原因留在對應 round，地圖改指有效版本。使用者修正須標明是本次例外、可重用經驗或長期 policy。

## INDEX 模板

角括號內說明該欄位要填的內容。未知填「未知」及待確認事項；不適用填原因。建圖時按任務填寫，保留可供接手者定位的標題。

```markdown
# <任務名稱>

**讀者：** agent。<本任務要交付的結果與用途。>

## 目標與有效 policy

- 目標原話：<原話、來源、時間與適用範圍。>
- 結果用途：<誰會用結果，做哪個決定。>
- 有效 policy：<原話、條件及必要原文入口。>
- 使用者修正：<本次例外／可重用經驗／長期 policy，連到記錄原話的 round。>
- 求助與通知：<觸發條件、使用者不在線時的處理。>

## 驗收階梯與戰略階段

| 階梯 | 使用者可接受的狀態 | 所需證據 | 目前狀態與 round |
| --- | --- | --- | --- |
| <階段> | <可觀察的接受狀態> | <資料與判讀要求> | <未開始／進行中／已接受／受阻，引用> |

## 已知證據與目前物理圖像

- 直接觀察：<結論與數據／分析產物入口。>
- 工作假說：<暫定物理圖像、支持證據與競爭解釋。>
- 已失效觀察：<因環境、輸入或使用者修改而失效的觀察及原因。>

## 霧

- <會改變下一步的未知、待驗假說，以及需要什麼證據才能辨別。>

## Frontier 與下一輪

- 當前戰術目標：<最先要回答的問題，及它推進哪階驗收。>
- 下一輪：<round 路徑、下一動作與前置條件。>
- 接續狀態：<可推進／暫停／待確認／結案。>
- 暫停或求助：<停止位置、待答問題、解除條件。>

## 執行中操作與待確認結果

- <操作意圖、啟動時間、最後核對時間與狀態。沒有則填無。>
- <GUI 任務的環境、context、session、tab、操作等可用識別與對應 round。>
- <預期產物、已確認保存位置、仍未知的執行或寫入結果。>

## 預算與待使用者決定事項

- 預算：<適用的時間、金錢、設備占用上限與來源；未知／不適用時填原因。>
- 估算：<估計依據、已投入、剩餘額度與未知成本。>
- 待決定：<問題、選項、影響及等待誰回答。>

## 決策索引

| 時間 | 問題與裁定摘要 | 有效條件 | Round／原文入口 |
| --- | --- | --- | --- |
| <時間> | <目前採用的選擇> | <適用條件> | <round 路徑與原文位置> |

## 資料與經驗入口

- 原始資料：<來源、身分與保存位置。>
- 分析入口：<腳本、方法、輸入與衍生產物入口。>
- 知識入口：<主索引、routing 與本任務相關條目。>
- 交付與保留：<交付物、限制、保留期限或歸檔規則來源。>
```

霧保存影響選擇的未知。frontier 指出目前最先處理的問題。驗收階梯保存完成目標需要的證據，round 的 `accept` 只更新它實際支持的階梯。

決策索引連到判斷與原文，資料入口連到 artifact。兩者讓接手者按當前問題展開證據，無須掃描所有 rounds。

完成條件：接手者只讀 INDEX 就能找到下一步、有效授權及必要依據；未知成本、暫停與待確認結果都能直接辨認。

## 恢復與交接

1. 讀 INDEX 及它指向的必要 policy／決策原文，核對仍有效的授權。依 frontier 只展開當前決策需要的 round、知識與產物。
   完成條件：下一動作需要的授權與證據入口已找到；缺項已列成待確認問題。
2. GUI 任務先讀 [Run measure GUI](../../run-measure-gui/SKILL.md)，核對所連環境、context、tab、操作狀態與實際保存產物。純分析任務依 [Analysis](analysis.md) 核對輸入與分析入口。舊 session handle 只作上次觀察的線索，新 session 重新確認可用識別。
   完成條件：每個未結操作都有目前狀態，或明確標成未知；資料保存狀態已另行核對。
3. 比較文件與現況，將已完成、仍執行、失敗或回覆前中斷的操作更新到 INDEX。使用者改過設定或輸入時，重新判斷原假說與下一步是否適用，以現況規劃。
   完成條件：差異及失效觀察已記錄，下一動作有現況依據；執行不明的請求維持待確認。
4. 從 frontier 接續，或保存暫停。使用者中斷後，保留停止位置、待確認結果及等待說明，取得新指示才恢復自主工作。
   完成條件：地圖有可執行的下一輪，或指出等待哪個輸入。INDEX 有缺口時先修補或求助。

## Artifact 與保留

交接用圖像須保存到允許的持久位置，註明來源。MCP 圖像可能隨 server 關閉消失，round 應記實際另存的路徑。長期教學圖在沉澱時依知識規則精選。

保存意圖、操作完成、artifact 寫入成功分開記錄。結案時逐一交代 live operation；狀態未知的操作保留待確認。紀錄跨 session 保留，追溯資料的期限與歸檔依使用者的專案規則處理。

## 舊 task-records 欄位對照

既有紀錄轉為地圖與 round 時，保留原始來源入口。舊欄位的資訊放置如下。

| 原 INDEX 欄位 | 新位置 |
| --- | --- |
| 目標與有效 policy | 目標與有效 policy，原話、條件及修正分類一併保留。 |
| 戰略階段 | 驗收階梯與戰略階段，增加每階的接受狀態與所需證據。 |
| 已知證據與目前物理圖像 | 同名欄位保留目前摘要；演變與反例放在對應 round。 |
| 當前戰術目標與下一步 | Frontier 與下一輪；未解問題放在霧。 |
| 執行中操作與待確認結果 | 同名欄位；操作識別與詳細執行紀錄連到 round。 |
| 預算與待使用者決定事項 | 同名欄位保留預算、估算依據、剩餘額度與未知成本。 |
| 資料、經驗與決策入口 | 資料與經驗入口保存 artifact／知識位置，決策索引連回 round 原文。 |

舊 journal 的觀察、候選、理由、失敗路線與改道，依 [Round 的欄位對照](round.md#舊-journal-欄位對照) 承接。舊持久化時機由 [Round 的持久化](round.md#持久化) 承接；舊恢復與交接及圖像、資料與結案規則由本頁承接。
