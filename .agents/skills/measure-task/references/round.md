# Round

**讀者：** agent。開始一輪、結果改變下一步，或準備求助與交接時，用 round ticket 保存問題、執行證據與裁定。

## 一輪的邊界

一個 round 回答一個會影響下一步的問題。路徑為 `<task-dir>/rounds/NN-<slug>.md`，NN 在任務內遞增，slug 說明問題。候選動作可以是分析、補量測、互動分析、改道或求助。

round 保存帶時間的判斷轉折，取代 journal。例行讀取與未增加資訊的重跑可合併摘要。長推導、完整輸出、腳本與圖表放在任務 artifact，round 引用來源及與判斷相關的結果。

## Round 模板

角括號內說明欄位意義。尚未執行的欄位填待補，無法確認的結果填未知及待確認方法。

```markdown
# Round <NN>：<問題簡名>

**讀者：** agent。<本輪要辨別或驗證的問題。>

- 時間與狀態：<開始／更新時間，規劃／執行中／待確認／已裁定／暫停。>
- 地圖入口：<INDEX 的 frontier 與本輪所推進的驗收階梯。>

## 問題

<要回答什麼，為何現在需要回答，依據哪些既有觀察與假說。>
```

## 裁定

裁定作用於本輪的明確對象。單一 `accept` 可以接受一項證據，是否完成任務仍按地圖的驗收階梯判斷。

| 裁定 | 意義與後續 |
| --- | --- |
| `accept` | 結果可信且滿足本輪接受條件。註明支持哪階驗收，將未解限制留在地圖。 |
| `redo` | 本輪問題仍適用，但證據不足或執行有缺陷。寫明重做要改什麼、如何辨別。 |
| `reroute` | 新證據或成本使其他路線更合適。保留原路線條件與改道理由，開下一問題。 |
| `ask` | 下一步需要使用者裁決或補必要背景。列出已知、已試、選項與待答問題，維持相應暫停。 |

完成條件：每個已裁定 round 都能由觀察與知識依據追溯到裁定，下一輪或求助條件明確。可信的異常可以保留為結果；結論強度以證據支持的範圍為限。

## 持久化

以下事件發生時更新 round，並把目前有效狀態同步到 [Map](map.md)。

- 目標、policy、戰略或重要工作假說改變時，保留新舊版本、條件、原話及替換原因。
- 啟動長時間或高成本操作前，先記意圖、輸入、預算依據與預期產物。取得回覆後補記當時可用的 session、操作、tab 識別及狀態。
- 一輪結果改變下一步時，補齊觀察、物理圖像、知識依據與裁定，再更新地圖。
- 求助、使用者接手、中斷、暫停、交接或結束時，記停止位置、未結操作、待確認結果與接續條件。

中斷後的接續依 Map 的恢復與交接流程。持久化按事件發生，不依賴壓縮通知。

完成條件：上述事件的狀態已寫入 round 與地圖。接手者能分辨計畫、實際執行、已保存結果與未知，而非依對話補猜。

## 舊 journal 欄位對照

| 舊 journal 內容 | Round 位置 |
| --- | --- |
| 帶時間的重要觀察與結果 | 時間與狀態、執行紀錄與 artifact、觀察。 |
| 候選解釋與未解問題 | 問題、物理圖像。 |
| 考慮過的選項與選擇理由 | 候選與成本、選擇與預期觀察。 |
| 改道、行不通路線的條件與原因 | 裁定與依據、下一輪。 |
| 被替換的決定及使用者修正 | 裁定與依據保留原話與條件，地圖指有效版本。 |
| 分析腳本、圖表、長推導 | 執行紀錄與 artifact 引用任務內檔案與來源。 |

遷移時保留舊紀錄入口，將支撐當前 frontier 的內容連到相應 round。既有歷史可按問題分輪；尚未重新裁定的內容保留原判斷與時間，標明待確認。
