# Measure task

**讀者：** agent。用地圖掌握目標，以 round ticket 推進問題，依證據裁定下一步。

`<repo>` 是任務使用的 repo cwd。`<task-dir>` 是 `<repo>/.agent_state/measurement-tasks/<task-id>/`，既有任務沿用已確認的位置。下列文件連結相對於本 skill 解析。

## 1. 接收任務

取得目標、結果用途、policy 原話與條件、預算、求助及通知條件。追問會改變可行動作的缺口，沿用仍有效的授權。

地圖：建立或更新 `<task-dir>/INDEX.md` 前，讀 [Map](references/map.md)。INDEX 保存目前有效狀態，round 保存判斷轉折。開始或恢復任務時，按 [Knowledge](references/knowledge.md) 核對知識入口與初始化缺項。

預算：確認適用的時間、金錢與設備占用。成本未知時記下估算依據與限制投入的條件；跨夜或無人值守長跑須先有涵蓋該投入的授權。

分析：輸入是既有資料、任務要裁定分析結果時，先讀 [Analysis](references/analysis.md)，再套用後續步驟。

完成條件：地圖能指出結果用途、有效 policy、預算與求助條件。每個尚缺的必要條件都有待答問題，只推進不依賴該缺口的工作。

## 2. 建驗收階梯

把目標拆成使用者能看到並接受的狀態，為每階列出所需證據。近期階梯寫清楚，遠期保留條件分支。例如：

- resonator 找到，且窄掃確認。
- qubit 頻率與分支有證據支持。
- π 脈衝通過 AllXY。
- T1／T2 在工作點量到，且 fit 可信。

霧：把會影響下一步的未知與待驗假說留在地圖。frontier 是目前最先需要回答、能推進驗收階梯的問題，連到下一個 round。

完成條件：每階都有可核對的接受狀態與證據要求，frontier 指出近期問題及其未解條件。

## 3. 開 round ticket

每輪開始前讀 [Round](references/round.md)，建立 `rounds/NN-<slug>.md`。先定義問題，再比較重新分析、補量測、改道或求助的資訊價值與成本。

選擇動作時寫下理由、預期觀察，以及結果不同時如何辨別。估計要附依據，未知要列出；以剩餘預算評估投入。

完成條件：round 有一個待回答的問題、可行候選與成本、選擇理由及可辨別的預期觀察。

## 4. 執行並留下證據

量測：操作 GUI、啟動量測或核對 live operation 前，讀 [Run measure GUI](../run-measure-gui/SKILL.md)，由它處理 MCP 入口、現況核對與操作控制。

離線分析：使用既有資料與分析腳本，保留輸入、方法及產物引用。執行環境依 repo 的 MEASUREMENT 規則；分析分支依 Analysis reference。

按 Round 的持久化時機記錄執行。核對操作狀態及 artifact 的實際保存結果，將失敗或未知留在紀錄。

完成條件：round 能追溯本次輸入、執行與產物，或指出失敗／未知、已確認範圍及待確認事項。

## 5. 裁定結果

judge：裁定結果前，依 `<repo>/measure_knowledge/README.md`〈選擇查找入口〉查找適用條目。查找分支以該 README 為唯一權威。把用到的條目與適用限制記入 round。

分開寫直接觀察與暫定物理圖像。讀圖核對座標、單位、條件及分析假設。說明支持假說的證據、競爭解釋與會改變判斷的反例。分別判斷結果是否可信、是否達成該階驗收。

裁定記為 `accept`、`redo`、`reroute` 或 `ask`，定義見 Round。依據須連到本輪證據、judge 條目及有效 policy。缺少適用條目時，保留證據缺口，必要時求助。

完成條件：round 已寫觀察、物理圖像、知識依據、裁定與下一輪。接手者能辨認接受了什麼，或還缺什麼。

## 6. 更新地圖或求助

更新地圖的驗收階梯、目前物理圖像、決策索引、霧、剩餘預算與 frontier，連回支持這次更新的 round。有效 policy 有變動時保留使用者原話及適用條件，舊版本留在 round。

遇到目標、policy、風險取捨或必要背景需使用者裁決時，列出觀察、已試路線、選項與待答問題。使用者中斷或接手時，依 Map 維護暫停及重新核對現況。

完成條件：INDEX 能直接指出下一輪，或明確標成暫停及等待哪個輸入；執行中操作與待確認結果都已列出。

## 7. 結案與沉澱

交付結果、證據位置、適用條件與剩餘不確定性。未達目標時，交付進度、阻礙、已排除路線與下一個必要輸入。依 Map 保留可追溯紀錄，逐一交代仍在運行的操作。

沉澱：有新辨別方法、反例、限制或專家修正時，依 Knowledge reference 選 `route`、`judge` 或 `analysis` kind，寫入知識庫並 commit，不 push。當次數值與進度留在任務紀錄。

完成條件：交付能對照驗收階梯，live work 已交代；可重用經驗已記入知識庫及 commit，或記明本次沒有需新增的經驗。

## 恢復任務

恢復時先讀本 skill、既有 INDEX 與它指出的有效 policy／決策原文，按 Map 的恢復與交接流程核對現況。GUI 任務先經 Run measure GUI 核對 GUI；純分析任務核對輸入與分析產物。

從 frontier 開啟必要 round，確認下一動作仍適用後，接回步驟 3 至 6。INDEX 無法指出下一步時，先修補紀錄或求助。

完成條件：有效授權、當前狀態、失效的舊觀察與下一動作已核對；使用者中斷造成的暫停，仍由使用者的新指示解除。
