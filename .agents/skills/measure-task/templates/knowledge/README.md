# 量測知識庫

**讀者：** agent。本庫保存可重用的量測與整合分析判讀方法，供量測後判讀結果或遇到症狀時查找。當次目標、policy 與進度留在任務紀錄，歷史經驗不覆蓋使用者當前的目標、授權或安全限制。

知識入口是工作 repo 的 `measure_knowledge/`，可能是使用者管理的 symlink。Agent 保留既有共享連結，不建立、改向或修復它。共享入口不提供並行寫入隔離。

每條經驗放在 `experiences/` 下的一個資料夾，以 README.md 為入口，可包含方法、案例、圖片與離線分析腳本。不填入虛構案例。

## 選擇查找入口

1. 已知實驗名稱時，先查 [routing 的實驗名稱索引](routing.md#依實驗名稱)，再讀對應的 judge 條目。實驗名稱沿用 `zcu_lab/v2/<family>/<exp>` 的 `family/exp`，單 qubit 可省略 family，例如 `t1`、`mux/t1`。
2. 實驗名稱索引未命中，或只有症狀時，查同一份 [routing 的症狀表](routing.md#依症狀)，沿連結進入條目或相關章節。
3. 兩張表仍未命中時，在本 repo 用 grep 搜尋 frontmatter 與正文，例如 `grep -RniE '慢尾端|基線漂移|t1' experiences --include='*.md'`。先看命中條目的 `experiments`、`symptoms` 與「何時使用」，再決定是否展開全文。

從目前的判斷問題出發，不要求先猜對原因。查閱正常表現與品質依據，也查反例和限制。只展開需要的方法、案例、圖片或腳本，不一次讀完整資料夾或整座庫。

匹配到的文字只是候選知識。核對實驗條件、環境差異與未確認部分。曾在某 qubit 觀察到不等於僅適用於它，描述相似也不等於原因相同。

遇到互相衝突的經驗，保留差異並選擇能區分的證據。找不到適用內容時標示缺口，使用當前證據作暫定判斷，不把搜尋不到當成物理上不存在。

初始化受阻時回報；沒有可用經驗時不宣稱已查閱。是否繼續不依賴經驗庫的工作，依當次目標與 policy 判斷。

完成條件是知道目前選用的方法為何適用、尚有哪些限制，或已清楚記錄沒有足夠知識可用。

## 一條經驗放什麼

一個資料夾處理一個可獨立使用的判斷問題。每條經驗選一種 kind，README 使用該 kind 的固定標題與順序。若同一條同時處理流程選擇與單次結果判讀，拆成 route 與 judge，互相連結。

| kind | 處理的問題 | 內容範圍 |
| --- | --- | --- |
| `route` | 下一步做哪個實驗，何時回頭或停止？ | 前置條件、實驗順序、分支決策與各步證據。 |
| `judge` | 這次實驗結果是否可信，應接受、重做還是求助？ | 正常樣貌、症狀與候選原因、辨別動作及判斷依據。 |
| `analysis` | 如何用既有資料完成可重用的分析與驗收？ | 分析輸入、判讀規則、輸出驗收與適用限制。 |

### Frontmatter

每個條目的 README 在檔案開頭放 YAML frontmatter，五欄都要填。frontmatter 後放文件標題，正文首段使用 `**讀者：** agent。<用途>`。

```yaml
---
kind: judge
experiments: [t1, mux/t1]
symptoms: [慢尾端, 基線漂移, repeat 不一致]
scope: both
updated: 2026-10-21
---
```

| 欄位 | 用途 | 格式與合法值 |
| --- | --- | --- |
| `kind` | 指定條目回答的問題與正文骨架。 | 只能是 `route`、`judge`、`analysis` 其中之一。 |
| `experiments` | 供實驗名稱索引與搜尋匹配相關條目。 | YAML list，項目使用 `zcu_lab/v2/<family>/<exp>` 的 `family/exp`。單 qubit 可省 family，例如 `t1`；多 qubit 例如 `mux/t1`。填實際相關的實驗名稱，不用條目資料夾名稱代替。 |
| `symptoms` | 供症狀 routing 與全文搜尋匹配入口。 | YAML list，項目是可搜尋的症狀或判斷問題關鍵詞，例如 `慢尾端`、`repeat 不一致`。沒有固定列舉，沿用既有詞彙以便查找。 |
| `scope` | 標示方法適用的環境。 | 只能是 `sim`、`real`、`both`，分別表示模擬、真實量測、兩者皆適用。不把模擬案例當成真實硬體驗證，具體限制仍寫在正文。 |
| `updated` | 記錄最近一次修訂日期。 | 有效日期，格式為 `YYYY-MM-DD`，例如 `2026-10-21`。 |

### Judge 骨架

正常樣貌寫可觀察的特徵與合理變異。「症狀與候選原因」區分觀察與解釋，「辨別動作」列出能區分候選原因的證據。

```markdown
# 條目名稱

**讀者：** agent。判讀某個實驗的結果。

## 何時使用
## 正常樣貌
## 症狀與候選原因
## 辨別動作
## 接受／重做／求助
## 限制與反例
## 案例
```

### Route 骨架

決策樹寫每個分支的進入條件與下一步。「每步需要的證據」說明何種結果足以往下走；缺少必要證據或授權時，在「停止與求助」說明如何處理。

```markdown
# 條目名稱

**讀者：** agent。選擇實驗順序與下一步。

## 何時使用
## 前置條件
## 決策樹
## 每步需要的證據
## 停止與求助
## 案例
```

### Analysis 骨架

輸入寫資料格式、來源與必要條件。判讀規則說明分析方法，驗收寫輸出必須符合的條件，不以產生圖或 fit 成功代替判讀。

```markdown
# 條目名稱

**讀者：** agent。分析既有資料並驗收結果。

## 何時使用
## 輸入
## 判讀規則
## 驗收
## 限制與反例
## 案例
```

### 證據與安全

固定標題都保留，缺少內容時明寫未知或待補，不補造判斷。正文可用子標題展開物理圖像、成本取捨與其他文件入口。

分開保留已觀察的環境、推測適用條件、已知反例與未知範圍。環境變動後重新核對適用性，不能因為曾經成功就照做。

圖片附上來源、已知條件、該看哪裡、能支持什麼及不能支持什麼。文字要足以讓搜尋找到圖例。不要只連到 MCP session 暫存檔，也不要把圖像外觀當成通用門檻。

正式量測資料留在原本的 artifact 儲存位置，知識庫保存引用與必要的精選圖例。

可重用的離線腳本說明輸入格式、環境、輸出與副作用。使用前讀懂入口與相關內容，確認在當次授權內；不因為位於知識庫就視為已獲執行授權。保留資料來源，不覆寫原始量測檔。

## 何時修訂

新辨別方法、反例、適用限制、推翻原解釋的結果或專家修正，才值得長期沉澱。普通量測值和任務進度仍留在正式資料與任務紀錄。

新增前搜尋既有條目。相同判斷問題優先整合，不為每次案例另造一條幾乎相同的經驗。粒度變大而開始服務不同問題時，再拆分。

Agent 可自主修訂方法，說明新證據改變了什麼。區分觀察、解釋及驗證。使用者提供的專家判斷可作依據，但不標成實驗證實。多次引用也不等於多份獨立證據。

目前仍有判斷價值的反例與限制留在現行內容；淘汰的措辭交給 Git history。不能透過修改驗收方法降低當次目標或擴張 policy。

修改後確認合理的 routing 入口能找到它。Routing 只保存進入條件與連結，不複製正文。同一條目可有多個入口；先使用既有 domain，必要時才調整分類。

## 使用 Git

修改前確認操作目標是知識庫自己的 Git repo，而不是向上解析到外層程式碼 repo。查看既有變更，保留其他人的工作。共享 symlink 不提供寫入隔離，未確認協作安排時不併發修改同一內容。

一次提交整理一項有意義的知識變更，包含必要的正文、案例與 routing 更新。提交前讀 diff，檢查是否誤刪限制、加入錯誤來源或混入無關變更。不要替使用者提交其他未授權的修改。

需要追溯時讀 log／diff。需要撤銷時確認後續依賴，使用新的修訂或 revert 保留歷史，不用整庫 reset 丟棄後續工作。遠端 push 依使用者授權，不因本機 commit 而自動執行。

完成條件是修訂理由與依據可追溯、現行內容可搜尋、引用有效，且 Git 變更只包含本次知識工作。重要修訂可彙整通知使用者，不要求逐筆批准。

## 模擬案例的限制

模擬案例保存判斷方法與反例，不驗證真實硬體安全或校準效果。數值設定留在案例中；移轉時重新確認單位、功率、時序、phase convention 與適用模型。方法條目說明前提和停止條件，不能拿案例中的 gain、flux 或等待時間直接操作設備。
