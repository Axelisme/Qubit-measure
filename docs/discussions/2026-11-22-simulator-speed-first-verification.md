# 模擬器的時間門檻與驗證成本

## 結論

使用者將正常參數下的 180 秒模擬時間放在精度之前。完整終態 density 與各讀出 population 的最大絕對誤差在 `1e-2` 內時，選耗時較短的做法。為了不超過 180 秒，可以接受無法避免的較大誤差，但要記錄；誤差達 `1e-1` 時不採用。這取代把 `2e-3` 視為所有優化的硬門檻。既有較嚴的 guard、驗收與已完成的 family 比較仍有效。規則見 [ADR-0078〈歷史控制與精度驗收〉](../adr/0078-evolution-module-boundary.md#歷史控制與精度驗收)。

驗證改按成本排順序。只量目標實驗前後各一次完整 Run，不要求排他。只改 host 就用同 seed 比逐位結果；改數值則用同 seed 的縮樣和舊路徑比差。獨立參考能便宜取得就做，否則先標缺口，落地後補；完整表在收尾做，出問題先重驗受影響的場景。實機路徑、存檔格式或使用者看到的結果有變時，先驗再落地。使用者另同意 FTF projective 先依縮樣數值差交付，明列分類與 compact 統計的缺口。見 [ADR-0078〈先求效率，正確性事後補〉](../adr/0078-evolution-module-boundary.md#先求效率正確性事後補)。

## 問題

FTF 改用 Markov chain 時，舊真空路徑與候選的最大 population 差約 `3.3e-3`，超過原本的 `2e-3` 門檻。要判這個改動能不能交付，舊路本身有剪枝，不能當物理真值；獨立求解又比原先估計貴。另一個提案還要求每次跑整張量表，估計要排他使用 CPU 2.5 至 6 小時。兩筆成本都會擋住後續工作，卻沒有同樣的判斷用途。

## 考慮過的選項與比較

先改怎麼選速度與精度，再改何時取證。兩種做法若分別花 2 分鐘和 1 分鐘，誤差分別為 `5e-3` 與 `8e-3`，選 1 分鐘的。若較準的做法要 5 分鐘，另一個 2.5 分鐘、誤差 `3e-2`，可選後者但須記錄差距；達到 `1e-1` 就不能用時間換精度。

獨立參考回答的是物理模型內的精度，縮樣前後比回答的是遷移差。保留兩項，不要求同時完成。參考過貴時可用收斂外推，或從較短、較小的同型問題推估實際規模，寫明假設、覆蓋與不確定度。驗證的成本以不超過優化省下的時間為目標。

## 被否決的選項與理由

- 維持 `2e-3` 硬門檻，或在都達標時優先選略準的。使用者選的是操作員少等的方案。
- 每個數值改動都先做獨立參考。FTF 的局部遷移差已量得到，完整參考仍貴且可能無法界定誤差。延後可保留真正的精度檢查，不需拿舊路或 floor 0 冒充真值。
- 全表當關卡，或只取消全表、其他仍照舊。完整表適合整批結案，不能代替目標實驗的成對耗時，也不必讓每項優化排隊。改用非排他的前後各一次，記實際條件。
- 不量誤差或不設精度底線。使用者同意獨立參考，只要求控制成本，並且明訂底線。

## 留下的問題

[FTF Markov 收據](2026-11-22-ftf-projective-markov.md#量到什麼還缺什麼)只涵蓋縮樣遷移與部分獨立精度；未覆蓋的情況須標明，不當作通過。落地後若獨立參考證實誤差超過 `1e-2`，須回頭處理。是否接受時間例外，仍需正常參數的完整 Run 與誤差數字。

## 依據

2026-11-22，使用者：「我会以模拟效率为优先考量。应该说，时间门槛控制在三分钟内为优先考量，再来才是精度。精度我希望能。控制在十的负二次方，但是有时候无可避免的会超过，那就算了吧。」「我认为，嗯，我设一个精度底线好了，就是大概是十的负一次方。」

同日，使用者說：「我想优先把效率提高，再检查正确性」，對改驗證時序的五項提議答「A」。對參考解說：「你要注意参考解的计算时间成本，不要花太多时间在这东西上面。你可以用比如说外推的方法」。原始討論與取證工作檔未入庫，取捨與證據範圍已列在本文。
