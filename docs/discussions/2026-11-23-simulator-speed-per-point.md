# 模擬器速度改按每格點

## 結論

使用者把掃描實驗的模擬速度目標改為平均每格點不超過 0.1 秒。格點數是 Result 掃描軸長的乘積，不乘 rounds。無掃描軸而只取 shots 的實驗仍以整次核心耗時不超過 180 秒為目標。逐次評估型每次 acquire 過的評估算一點，拒幅與未走到的候選另報。規則見 [ADR-0078〈模擬器速度目標〉](../adr/0078-evolution-module-boundary.md#模擬器速度目標)。

使用者接受為減少量測成本縮減外層軸或 rounds。報表分開寫縮減場景的實測核心耗時、每點平均與判定，以及按工作量比例算出的完整場景估值。估值不能當成完整場景實測。缺完整核心時不外推。操作見[牆鐘工具](../../tools/README.md#實驗-run-牆鐘)。

## 問題

原目標以每個實驗的 180 秒為單位。一維場景加點數或同時增加兩軸時，工作量改變，不能沿用同一時間當作相同速度。全跑每個長場景也提高了量測成本。

## 考慮過的選項與比較

- 維持整次 180 秒。無掃描軸的 shots 實驗沒有格點可除，保留原來的單位；有掃描軸時改以每個格點比較。
- 只改文件，由讀者自己除。工具原本就持有各次 acquire 的核心耗時；同一份報表納入 Result 格點與判定，讀者不用另查軸長或自行判斷例外。
- 只量完整場景，或先固定縮減輸入再外推。完整場景能直接量固定成本與每點成本；縮減量測省時間，但線性比率也會放大固定成本。使用者接受分欄呈現兩者。

## 被否決的選項與理由

- 對有掃描軸的實驗繼續沿用 180 秒。使用者指出時間門檻應隨格點數改變。
- 只在 ADR 改目標而不改工具。使用者採納包含每點報表的方案。
- 把逾時前綴視為縮減場景。兩者工作量來源不同：前綴沒有跑完，只有核心下限；縮減場景在 Run 前固定配置，仍需跑完才能外推。

## 留下的問題

本次沒有重跑正式全表。新的判定只適用各自的場景與配置，不把舊 180 秒表的結論換算成新門檻結果。核心耗時仍讀完整 Run 的編譯、演化、讀出與 raw materialize。精度規則與 paired kernel 比較照舊。

## 依據

- 2026-11-23，使用者：「我意識到優化器評測時間依賴於點數，那應該改成平均每點0.1s，每軸至少會有31點來攤平固定成本」。對不乘 rounds、shots 維持 180 秒、逐次評估每次一點，答：「都對，但我接受場景使用外插來減少測量時間成本」。原始對話未入庫。
- 部分推翻[完整 Run 的核心耗時裁決](2026-11-21-simulator-core-time.md)所用的 180 秒。保留核心定義和下限語意，也保留[時間優先與精度底線](2026-11-22-simulator-speed-first-verification.md)的取捨。
- 遵循[牆鐘工具量手選場景](2026-11-23-curated-wall-time-scenes.md)的分母：由維護者決定哪些場景入表，不用 adapter inventory 代替。維護者核對縮減 path 和完整值，工具不推導完整 Form 預設。
