# 圖磚沿用存檔幾何

## 結論

使用者選 A。同一張 Figure 以存檔 PNG 的 12×9 in 排版，畫面只按可用空間等比縮放，多餘的地方留白。使用者接受字跟著圖縮小，換取同一張圖在各面保持同一版面。現行規則見 [ADR-0069](../adr/0069-experiment-core-and-frontends.md#圖以固定存檔幾何排版)。

## 問題

舊圖磚把 Figure 拉到各自的長寬並重新排版。[GE 診斷圖的交付討論](2026-11-22-ge-gate-split-from-diagnostic.md)記錄了碰字的例子，證據來自 360×375 px 的離線參考磚。寬磚則可能把圖拉扁。同一張圖換頁或改視窗寬度就會改變版面。

## 考慮過的選項與比較

- A 改顯示方式。用存檔的 4:3 排版，整張圖縮到剛好放入可用空間。窄磚與寬磚留下的空白方向不同，但圖內元素的相對位置不變。小磚的字會跟著整張圖變小。
- B 只改文件。即使把 R7 收窄到固定尺寸，GUI 繼續依磚形重排，同一張圖在不同面仍會改變版面。

前一天的 [Data 讀圖討論](2026-11-22-data-figure-reading.md)從窄 Save 頁的需求出發。使用者提醒：「那注意排版啊，那个 GUI 的版面配置可能不是正规的四乘三或者什么的，然后字体大小之类的要注意缩放，比如说在 Save 页面可能会变得比较窄」。當時保留分組縮圖與同頁的 `View figure`，使用者說「我觉得还不错，所以就保留」。這次保留選圖和入口，只取代兩個機制：

1. Data 閱讀面原本依閱讀尺度重繪，不縮小字級，放不下就捲動。改成以固定幾何排版，整張圖等比放入閱讀面。
2. R7 原本要在各 GUI 的實際尺寸檢查版面。改成只在固定存檔幾何的 PNG 檢查字級、刻度與圖例。各 GUI 面驗整圖是否等比嵌入、留白及無裁切。

## 被否決的選項與理由

B 留下原問題。依磚形重排再放大字也不是使用者要的做法，放大的字會多占圖面空間。

## 留下的問題

縮放後仍要確認互動畫布的點擊與縮放對準原資料座標。各實驗自己的圖面缺口不在這次裁決範圍。

## 依據

使用者於 2026-11-23 選 A，理由是「那我会选 A， 这样的话就不需要考虑各种形状的显示。」原始討論工作檔未入庫；[ADR-0069](../adr/0069-experiment-core-and-frontends.md#圖以固定存檔幾何排版)保留這次裁決的原話。
