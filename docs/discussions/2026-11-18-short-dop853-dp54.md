# 短 `dop853` row 改用 DP5(4)

## 結論

短 row 留在 `dop853` family，符合條件時在 CPU 或 OpenCL 使用 DP5(4)。`Engine.evolve(..., telemetry=True)` 的 `FamilyRouting` 分開計兩種 tableau 實際算出的端點。這讓呼叫端核對真正執行的方法，不必從預算或 family 名稱推測。現行契約見 [routing telemetry](../../lib/zcu_tools/simulate/evolution/README.md#routing-telemetry)與 [GPU backend](../../lib/zcu_tools/simulate/evolution/README.md#gpu-backend)。

## 問題

沒有可用 GPU 時，FTF 的 sub-GHz 成形雙 tone 掃描仍要在 CPU 積分完整驅動。短段也用 DOP853，一次 trial 要算 12 次 RHS；DP5(4) 要 7 次，但同容差下不能假定同樣準。增加第二套 tableau 之後，同一個 family 名稱也不再能區分實際用哪套方法。

## 考慮過的選項與比較

先比較短 CPU row 沿用 DOP853，或在固定預算下用 DP5(4)。原型把兩個局部容差都除以三，並以量過的 10 µs 為上限。正式 CPU 驗收用 d=24 的 `simultaneous_drive`，24 點、7 workers，對既有 CPU 路徑做三組獨占 ABBA。wall 中位加速為 1.4986×。名目門檻是 1.5×，使用者於 2026-11-18 接受實測值，沒有把它四捨五入報成達標。

在同一批 24 個點逐點比較兩版輸出，完整複數 density 的最大元素絕對差為 `3.0444e-5`。另用真實 FTF 的 960-knot 高 gain 單點，對照以兩級容差驗收收斂的獨立 Lindblad 參考解。CPU DP5(4) 在該點的完整複數 density 最大元素絕對誤差為 `2.9178e-5`。

OpenCL 等實機比較再選。Linux Intel Arc 上，兩側以相同的 24 點、7 workers 與預算交錯量測，只比較同一裝置上的兩套 tableau。d=24 和 d=32 的 ABBA 中位加速分別為 1.4700×、1.6132×。兩者對獨立參考解的完整 complex density 最大差都低於 1e-3，因此 OpenCL 也採用 DP5(4) 的短段規則。這遵循 ADR-0078 的[固定預算](../adr/0078-evolution-module-boundary.md#固定預算找適合的場景)與[先驗精度](../adr/0078-evolution-module-boundary.md#先保證正確再優化瓶頸)兩條規則。

精度矩陣保留同時播放兩個 sampled tones、d=24、每 tone 960 knots 的形狀，但在測試內重建輸入。這一格用獨立參考解檢查完整 density；真實 FTF 上的誤差與耗時由上述工作負載量測回答。兩組證據不能互換。這也遵循 [ADR-0078 的凍結數值不入庫規則](../adr/0078-evolution-module-boundary.md#凍結數值輸入與參考解交接)。

## 被否決的選項與理由

- 新增 family 或公開 tableau 選項。兩套 tableau 積分同一個方程，使用者提供的是誤差預算，不必指定 solver。多一個 family 也會改變既有白名單與診斷的意義。
- 只從 family 算端點，或把 method 寫進 routing JSONL。前者看不出實際 tableau；既有 JSONL 是 family 聚合，沒有逐 row 方法欄位。公開 `FamilyRouting` 的端點計數已可核對實際執行，不必改記錄格式。
- 把完整 FTF frozen input 放進精度矩陣。那會把實測輸入帶進日常測試，也違反凍結數值不入庫的規則。合成案例能保留要測的維度和 knot 支援。

## 留下的問題

`overlapping_shaped_tones` 的非獨占量測逾時，沒有可判讀的 slowdown 結果，不算通過。Intel Arc 的結果不代表 Windows 或其他 OpenCL driver 已驗證。

## 依據

CPU 數字來自成對驗收；GPU 數字來自 Intel Arc 上的成對驗收與兩級容差收斂的獨立參考解。原始工作檔未入庫。精度矩陣如何重建輸入及驗證參考解見 [測試文件](../../tests/README.md#evolution-精度矩陣)；選路與數值分工見 [ADR-0078](../adr/0078-evolution-module-boundary.md#內部允許實質耦合dispatch-擁有決策知識)。
