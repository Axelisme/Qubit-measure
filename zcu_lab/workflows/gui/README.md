# workflows/gui — Workflow form attachments

**Last updated:** 2026-10-09，同一 run 的 tunables RPC

這個 package 擁有具體 workflow 的表單、明寫的 to_cfg 與 Qt panel attachment，不實作通用 editor 或 Engine。Native workflow definitions 不依賴這些 GUI attachments。

T1PlanForm 編輯 absolute flux range/list、delay points 與共用 drive/readout ModuleInput。to_cfg 以 captured library 的公開 factory 解析 ref/inline，轉成 native modules，展開 setpoints，接 host 的歷史 RunSnapshot。缺 root、錯 family 或 materialization 失敗回報 consuming-field error。Native ModuleCfgFactory.from_core 接同一 materialization context，arb 與 flat_top arb ramp 的播放路徑固定在 captured asset directory，不讀 global repository。T1 drive 若是純 arb，在 qub_pulse 回 consuming-field error，因為 Length-Rabi 需要改 length 而 arb duration 固定。Flat_top 的 arb ramp、direct arb readout 與 flat_top arb readout ramp 繼續支援；不加入 gain-Rabi 或 time-scaling。非 arb flat_top 的 length 沿 native 總長語意原值直傳。Plan 不含完整 cfg、template 或 acquisition grid。T1PlanPanel preview 先阻擋 local parse errors，再產生 native T1Plan，不 Start 或捕捉來源。

初始 pi_length_us 是必填的 Rabi-range estimate。Defaults 只從固定 capture 的 qubit.module.x180.waveform.length 預填可改的 expression，缺值或不可讀就留空，不使用 simulator 常數或其他模組。T1WorkflowWindow 的 Start 從當次固定 capture 驗證輸入，以 validated pi_length_us 與 native module scalars 建 Calibrated seed。Native T1Plan 不新增此欄位。Window 將固定 context/storage/device capture 與 provenance 交 WorkflowController，在 worker 持 lease 啟動 native run；pending token 不代表 Engine 已接受。Stop 與關閉視窗使用同一 pending controller，producer 返回後才完成 plots。Pause/Resume 的公開 controls 與按鈕使用同一 native run。Pause 保留 plan/input capture 與 Plots lifetime，Resume 重新取得 lease 後只捕捉 cached native devices。整個 run 終止才解除 plan/input 鎖定。T1WorkflowWindow.create_remote_service以同一Window、session bus與owner組裝T1RemoteControlAdapter。RPC提供partial-input Start、native status及明填run_id的Pause／Resume／Stop，不另存run或重做target核對。Start的plan／tunables各送path-array／value batch，只送與defaults不同的欄位，空batch用當次capture的defaults。Host用既有FormState.write一次套用，不寫GUI draft或做tree overlay。Invalid回既有FormErrors path/message且不改panels；成功用既有reset(base)顯示實際提交input。GUI不傳batch時仍讀自己的panels及local parse errors。Pending token不代表worker接受，transport stop不取消native run。Records／PNG RPC、MCP、reload、獨立app及CP尚未完成；bounded接線不代表完整F5/P2或硬體驗收。

T1TunablesForm 與 nested CalibrationTunablesForm 定義使用者可編輯的普通值、Field 約束與呈現 metadata。Defaults 只讀 host 捕捉的 ParameterContext。general.ext.guess_us 存在時保留 expression 輸入，沒有 capture 或缺 leaf 時使用 native 暫定預設。明確 null 與無效引用值產生欄位錯誤，不以 fallback 蓋掉。

T1TunablesPanel 用 host 提供的 env 建立 state，嵌入通用 FormEditor，並公開 state 與 editor。Host 提交前檢查 editor.local_parse_errors。Panel 不提供 native preview、Apply／Discard／Start 或 live source capture。

FormState 處理 draft、驗證與 input 差異。to_cfg 只把合法普通值轉成 native T1Tunables。Expression 留在 FormInput，Engine journal 只記普通值。Host 決定何時提交；表單不更新 owner revision，也不操作設備。

T1TuningPanel 為已接受的 native T1 run 嵌入 T1TunablesPanel。它的 GUI Apply 與外部 JSON edit 共用 gui/app/workflows 的 TunablesHost。Host 保存已接受的expression input並提供Apply／Discard。GUI與外部edit提交當下完整普通值，不持GUI draft revision守衛。Engine保存數值revision，過渡期不檢查holder。Window.apply_tunables 先用 Controller.require_run_id 核對明填的 native target，再交同一 T1TuningPanel.apply_external。Pending startup 尚未接受時明確失敗，不碰 draft。workflow.tunables RPC 接 run_id 與 path/value batch，actor 固定為 agent/rpc。空 batch 提交當前完整 parsed input，不採 Start 的 defaults-only 語意。Model-invalid input 留在 shared draft，RPC 保留 FormErrors 的 path/message。只有成功才更新 accepted input/base 並清 local text。Engine 拒絕 lifecycle 或 journal failure 時不重試，也不假回成功。Paused Apply 後 Resume 保留已提交 records，未提交步驟用新 revision 重做。這個 caller 不 Start、capture、安排 worker 或保存 input 檔案。
