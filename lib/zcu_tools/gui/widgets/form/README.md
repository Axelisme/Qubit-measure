# gui/widgets/form — Form draft view

**Last updated:** 2026-10-15, field errors tint controls and lead row tooltips without adding height; bold click fold titles (▸／▾) replace the Expand/Collapse buttons, take Tab focus and fold on Space or Enter, and a section's unit follows its name; one schema per captured env and one publication per accepted commit; text commits on Enter or focus loss, Expression-to-Direct fills the computed value, and an option holding one ordinary model draws that model's rows; the shared FormEditor, value-widget helpers and host submission boundary

FormEditor renders caller-owned FormState using a host-captured FormEnv. Parsed input writes the draft. A text row commits its text when the user presses Enter or the field loses focus, not on each keystroke, so typing does not change state, preview or the host's Run admission; text that already shows the state's input writes nothing. Read-only rows and a detached editor commit nothing, and an external publication redraws a row's uncommitted text with the state's input. Checkboxes, dropdowns, the Enabled box and the Expression action write at once. Incomplete text and parse errors stay in the Qt view. The generic local_parse_errors query lets hosts reject submission while state still holds an earlier valid value.

A host that checks or rewrites input before it reaches the draft passes `write=`: every parsed batch (one field path to its JSON input) goes to that callable instead of `state.write`, and the editor still reads and subscribes to the same FormState. Without it the editor calls `state.write` itself, as the workflows host does. The callable refuses a batch by raising `gui.form.WriteRejected(message)` before writing: the field keeps the typed text (a checkbox, dropdown or Enabled box shows the state's value again) and shows the host's message. That input is view-local like unparseable text, so local_parse_errors reports it and discard_local_text drops it. The editor catches only WriteRejected; other exceptions propagate. A host that passes `write=` also passes `run_command=`, and passing only one raises ValueError: every triggered option command (path, name) then goes to that callable, which runs it on the same state through the host's guards, instead of `state.run_command`. A WriteRejected from it shows at the field like a rejected write.

Rendering cost stays bounded by the captured env. The editor computes the input schema once for the env it is built with and reuses it for every publication; only refresh(env) computes it again, even for the same capture. An accepted write publishes once: when the state's own publication already redrew the editor, the commit does not preview or redraw again, and only an unchanged or rejected write redraws to update view-local errors. set_editing_enabled with the mode the editor already has does nothing.

The view projects the public input schema and read-only FormPreview. It does not import core walkers or evaluate expressions. Core owns evaluation, model validation, choices and branch defaults. The view owns controls, error display and subscription lifetime. Sequences and typed mappings are whole leaves. Detach and close do not reset or submit the caller's state. discard_local_text drops view-local unparseable text and redraws the current state. The host separately resets its draft on Discard; the renderer does not own that policy.

Every field whose schema lists `x-form-options` shows one non-editable dropdown, `form.input.<path>`, and the list alone decides its items: Literal, Enum, choices, tagged unions, and the module and waveform selections (None, library keys, each Inline kind) that a Form generator declares. Items are the option labels in schema order, with each option's value as item data. The first option that matches the input by the core's Option rule is selected; the view does not read unions, tags, libraries or defaults. A present input that no option matches stays in state with its errors and shows as a last selected `<value> (missing)` item: a nonempty string as itself, other JSON as its JSON text. An unfilled field selects nothing. Choosing an option writes its value at the field in one batch; the core starts a new branch from that branch's defaults and carries nothing over. While the selected option has fields, their rows show under the dropdown, without the tags its value fixes; such a field has no Enabled box, because a nullable one lists None as an option. When those drawn fields are a single ordinary model, not nullable and without options (such as an inline module or waveform wrapper), that model has no titled row of its own: its rows show directly under the dropdown with their full paths, and errors at the model's own path show at the option row. The rule reads the schema shape only, never field or class names; a lone nullable model keeps its Enabled box and a lone field with options keeps its dropdown. A tagged union without the list raises ValueError rather than guessing a branch.

The dropdown's right-click menu lists the selected option's schema commands as QActions `form.command.<path>.<name>` (also in the dropdown's actions()), for example a library key's "Convert to inline". Triggering one calls `state.run_command(path, name, env)`, or the host's `run_command` route. The view never copies or converts values itself.

Text rows (int, float, complex and str values typed into a text field) offer Direct and Expression modes. The view offers them exactly where the core's schema has an Expr alternative; it does not decide which fields are text fields. Dropdown and checkbox rows have no Expression action; a dropdown opens a right-click menu only for its selected option's commands. A text row has no mode dropdown: its text field's right-click menu ends with a checkable Expression action after the standard items, and the row tooltip says so. Direct text stays literal, including text starting with $. Expression mode writes an explicit envelope to FormState. Switching a committed Expression whose preview has a value back to Direct writes that value in one batch through the same write route, at full precision and complex values in their input codec, even when the model then rejects it (for example out of range); the text then shows it. An expression that does not compute, and text that is uncommitted, unparseable or host-rejected, switch with the text kept: a numeric row shows its parse error, a str row writes the text as a literal. The view displays the core-resolved preview with an equals prefix: `= 5000.125` for a number and `= "yoko1"` for a JSON-quoted string, without repeating the expression. It shows alias-naming errors without fallback. It never replaces the authored expression with the resolved name.

The value label shows only an Expression-mode resolved value; Direct input is not echoed. An Expression-mode input has a light tint that follows the theme, so it stands out in light and dark themes and its text stays readable. Empty value labels are hidden and take no space. Field errors add no row height: Direct text inputs and dropdowns get a light-red tint mixed from the palette's Base, while checkbox and model-section name labels turn red like “Contains errors”. An invalid Expression input keeps its Expression tint and gets a red 1px border. The coloured input or name label carries the boolean Qt property `formError`. The row tooltip starts with the error, then keeps its description and mode hint; clearing the error restores the tooltip and normal colours. Errors are tooltip-only, not selectable text. The form-wide `form.error` label and group “Contains errors” notes remain unchanged.

A one-value Literal (schema const, not nullable) has nothing to choose or compute: its row shows the value as frameless read-only text, without a dropdown or Expression action. Fields the schema marks hidden have no row: Display(hidden=True) fields and one-value structural tags outside a union, such as a standalone LinRange's kind. Their input stays in state, and their errors go to the nearest drawn ancestor row or the form-wide error label. A float with schema decimals shows Direct and resolved values rounded to that many digits with trailing zeros trimmed; typed text with more digits stays as typed and the state keeps every digit. Section titles come from the schema.

Rows sit close together and nested groups use small margins. The labels of one model level share a left-aligned column as wide as its widest label, so that level's controls start at one left edge; each nested group has its own column. The editor has no outer margins; hosts add them.

The editor has no fold buttons. Group blocks and model sections (a nested model, a tagged union, an option row whose selected option draws fields, an enabled nullable model) fold by a left-button click on their title: a bold ▸ (folded) or ▾ (expanded), then the label. Tab stops on every fold title, while a click does not focus it; a focused title shows the style's focus frame, and Space, Return or Enter folds or unfolds it. No other key folds a title, and keys typed into an input never reach one, so Enter there still commits its text. A model section's title, `form.fold.<path>`, is its row's name label in the level's label column; a group's title is `form.fold.group.<path>.<group>` (`form.fold.group.<group>` at the root). A unit follows the title, after the row's dropdown or Enabled box if any, so a Sweep reads `▾ Freq MHz`. Other rows show their name in normal weight without a mark, and a click on it does nothing. A disabled nullable model draws only its plain label and its Enabled box (`form.enabled.<path>`), without a fold mark or an empty box; enabling it rebuilds the row with its title and rows.

Fields the schema marks `x-form-group` sit in a foldable group block (`form.group.<path>.<group>`, `form.group.<group>` at the root) of their drawn model level; under an option row that draws a lone model's rows, path is the option row's path. A level shows its ungrouped rows first, then its group blocks in the order of each group's first field; a group whose fields are all hidden has no block. The group's fold title joins the level's label column and the block's rows get their own column, like a nested model. Groups start folded and model rows follow Display collapsed. The editor remembers the folds the user sets on groups and model rows by path, so a rebuild after an option or activation change keeps them. A folded group does not unfold for errors; its header shows a "Contains errors" note while any of its rows shows one. One stretch below the last row takes spare height, so nested groups do not grow.

set_editing_enabled(enabled=False) makes the form read-only but readable, for hosts that must not let the user change input, such as the workflows host during a run. No control is disabled, so nothing turns grey. Text fields are read-only QLineEdits: their text can be selected and copied, and their right-click menu keeps only the copying items, with the Expression action disabled. Dropdowns and checkboxes keep showing their value in normal colours but ignore clicks, wheel turns and keys other than Tab. A wheel turn over them scrolls the enclosing scroll area. Option command actions stay listed but disabled. Fold titles still take Tab focus and fold and unfold on a click, Space, Return or Enter, without writing state. External state publications still show. enabled=True restores every edit and the mode switch.

The workflows host's WorkflowFormPanel (`gui/app/workflows/panel.py`) passes neither `write` nor `run_command`; the measure Run panel passes the tab resource's `write` and `run_command`. Apply, Discard, Start, revision checks and persistence stay with the host.
