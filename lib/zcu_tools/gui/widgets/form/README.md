# gui/widgets/form — Form draft view

**Last updated:** 2026-10-13, one Inline-or-key dropdown for str-or-model and ModuleInput fields; right-click Expression action and tinted Expression inputs; foldable Display group blocks and user folds kept across rebuilds; key-or-inline rows follow the core's x-form-key-or-inline marker; host write callable and WriteRejected; decimals, hidden rows, fixed Literals and section titles

FormEditor renders caller-owned FormState using a host-captured FormEnv. Parsed input writes the draft. Incomplete text and parse errors stay in the Qt view. The generic local_parse_errors query lets hosts reject submission while state still holds an earlier valid value.

A host that checks or rewrites input before it reaches the draft passes `write=`: every parsed batch (one field path to its JSON input) goes to that callable instead of `state.write`, and the editor still reads and subscribes to the same FormState. Without it the editor calls `state.write` itself, as the workflows host does. The callable refuses a batch by raising `gui.form.WriteRejected(message)` before writing: the field keeps the typed text (a checkbox, dropdown or Enabled box shows the state's value again) and shows the host's message. That input is view-local like unparseable text, so local_parse_errors reports it and discard_local_text drops it. The editor catches only WriteRejected; other exceptions propagate.

The view projects the public input schema and read-only FormPreview. It does not import core walkers or evaluate expressions. Core owns evaluation, model validation, choices and branch defaults. The view owns controls, error display and subscription lifetime. Sequences and typed mappings are whole leaves. Detach and close do not reset or submit the caller's state. discard_local_text drops view-local unparseable text and redraws the current state. The host separately resets its draft on Discard; the renderer does not own that policy.

Tagged branch identity comes from the schema owner's x-form-discriminator-values metadata, not the current choices enum. Selector options intersect that identity with current leaf options. Empty choices keep the current branch visible and its input unchanged. All discriminators are structural selectors: they determine model shape and branch defaults. Their schema and controls offer only ordinary typed tags, without expression mode.

String value leaves, including Literal[str] and string Enum values, offer Direct and Expression modes like numeric fields. A row has no mode dropdown: its input's right-click menu ends with a checkable Expression action (after a text field's standard items), and the row tooltip says so. Direct text stays literal, including text starting with $. Expression mode writes an explicit envelope to FormState. The view displays the core-resolved preview as `$flux_dev = "yoko1"` and shows alias-naming errors without fallback. It never replaces the authored expression with the resolved name.

A field the schema marks `x-form-key-or-inline` holds a library key or an inline model and shows one non-editable dropdown, `form.input.<path>`: Inline first, then the schema's x-form-library-keys. Core marks each untagged str-or-model field (`str | Model`, such as a pulse's waveform or a readout's pulse_cfg) and each ModuleInput (`qub_pulse`, `readout` in workflows); the view reads only that marker. For a ModuleInput the ref branch's name carries the keys: every library module key, or those among the form's choices for that name. Choosing a key writes it (a ModuleInput writes kind "ref" and the name in one batch); choosing Inline writes `{}` or kind "inline", the core's inline defaults (a ModuleInput copies the referenced library module), and shows the inline rows below; a ModuleInput shows its module without a kind row. A key the list lacks (deleted, renamed, or written over the wire) shows as a selected `<key> (missing)` item; the state keeps it and the field's errors still show. Without listed keys the dropdown has only Inline, plus that missing item. An unfilled field selects nothing. The GUI cannot type a key; wire writes can hold any key.

The value label shows only an Expression-mode resolved value; Direct input is not echoed. An Expression-mode input mixes a little of the palette's highlight colour into its base colour, so it stands out in light and dark themes and its text stays readable. Empty value and error labels are hidden and take no space; field errors appear under their row. A choice leaf with expression support (Literal, string Enum or a choices entry) shows a dropdown of only the current choices in Direct mode and a text field in Expression mode. Returning to Direct selects the resolved value when it is a current choice, otherwise the last Direct choice. Discriminators keep their plain tag dropdown.

A one-value Literal (schema const, not nullable) has nothing to choose or compute: its row shows the value as frameless read-only text, without a dropdown or Expression action. Fields the schema marks hidden have no row: Display(hidden=True) fields and one-value structural tags outside a union, such as a standalone LinRange's kind. Their input stays in state, and their errors go to the nearest drawn ancestor row or the form-wide error label. A float with schema decimals shows Direct and resolved values rounded to that many digits with trailing zeros trimmed, using the spinbox module's trimmed_decimals; typed text with more digits stays as typed and the state keeps every digit. Section titles come from the schema; a placeholder selector (no branch selected yet) takes the tag title of the branches, like a selected one.

Rows sit close together and nested groups use small margins. The labels of one model level share a left-aligned column as wide as its widest label, so that level's controls start at one left edge; each nested group has its own column. The editor has no outer margins; hosts add them.

Fields the schema marks `x-form-group` sit in a foldable group block (`form.group.<path>.<group>`, `form.group.<group>` at the root) of their model level. A level shows its ungrouped rows first, then its group blocks in the order of each group's first field; a group whose fields are all hidden has no block. The group title joins the level's label column and the block's rows get their own column, like a nested model. Groups start folded and model rows follow Display collapsed. The editor remembers the folds the user sets on groups and model rows by path, so a rebuild after a branch, key-or-inline or activation change keeps them. A folded group does not unfold for errors; its header shows a "Contains errors" note while any of its rows shows one. One stretch below the last row takes spare height, so nested groups do not grow.

The workflows host's WorkflowFormPanel (`gui/app/workflows/panel.py`) is the current caller; it does not pass `write`. Apply, Discard, Start, revision checks and persistence stay with the host. This tool does not migrate CfgSchema or Measure.
