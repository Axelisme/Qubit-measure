# gui/widgets/form — Form draft view

**Last updated:** 2026-10-14, one option dropdown drawn only from the schema x-form-options list, with the selected option's fields below it and its commands in the right-click menu; host run_command route beside write

FormEditor renders caller-owned FormState using a host-captured FormEnv. Parsed input writes the draft. Incomplete text and parse errors stay in the Qt view. The generic local_parse_errors query lets hosts reject submission while state still holds an earlier valid value.

A host that checks or rewrites input before it reaches the draft passes `write=`: every parsed batch (one field path to its JSON input) goes to that callable instead of `state.write`, and the editor still reads and subscribes to the same FormState. Without it the editor calls `state.write` itself, as the workflows host does. The callable refuses a batch by raising `gui.form.WriteRejected(message)` before writing: the field keeps the typed text (a checkbox, dropdown or Enabled box shows the state's value again) and shows the host's message. That input is view-local like unparseable text, so local_parse_errors reports it and discard_local_text drops it. The editor catches only WriteRejected; other exceptions propagate. A host that passes `write=` also passes `run_command=`, and passing only one raises ValueError: every triggered option command (path, name) then goes to that callable, which runs it on the same state through the host's guards, instead of `state.run_command`. A WriteRejected from it shows at the field like a rejected write.

The view projects the public input schema and read-only FormPreview. It does not import core walkers or evaluate expressions. Core owns evaluation, model validation, choices and branch defaults. The view owns controls, error display and subscription lifetime. Sequences and typed mappings are whole leaves. Detach and close do not reset or submit the caller's state. discard_local_text drops view-local unparseable text and redraws the current state. The host separately resets its draft on Discard; the renderer does not own that policy.

Every field whose schema lists `x-form-options` shows one non-editable dropdown, `form.input.<path>`, and the list alone decides its items: Literal, Enum, choices, tagged unions, and the module and waveform selections (None, library keys, each Inline kind) that a Form generator declares. Items are the option labels in schema order, with each option's value as item data. The first option that matches the input by the core's Option rule is selected; the view does not read unions, tags, libraries or defaults. A present input that no option matches stays in state with its errors and shows as a last selected `<value> (missing)` item: a nonempty string as itself, other JSON as its JSON text. An unfilled field selects nothing. Choosing an option writes its value at the field in one batch; the core starts a new branch from that branch's defaults and carries nothing over. While the selected option has fields, their rows show under the dropdown, without the tags its value fixes; such a field has no Enabled box, because a nullable one lists None as an option. A tagged union without the list raises ValueError rather than guessing a branch.

The dropdown's right-click menu lists the selected option's schema commands as QActions `form.command.<path>.<name>` (also in the dropdown's actions()), for example a library key's "Convert to inline". Triggering one calls `state.run_command(path, name, env)`, or the host's `run_command` route. The view never copies or converts values itself.

Text rows (int, float, complex and str values typed into a text field) offer Direct and Expression modes. The view offers them exactly where the core's schema has an Expr alternative; it does not decide which fields are text fields. Dropdown and checkbox rows have no Expression action; a dropdown opens a right-click menu only for its selected option's commands. A text row has no mode dropdown: its text field's right-click menu ends with a checkable Expression action after the standard items, and the row tooltip says so. Direct text stays literal, including text starting with $. Expression mode writes an explicit envelope to FormState. The view displays the core-resolved preview as `$flux_dev = "yoko1"` and shows alias-naming errors without fallback. It never replaces the authored expression with the resolved name.

The value label shows only an Expression-mode resolved value; Direct input is not echoed. An Expression-mode input has a light tint that follows the theme, so it stands out in light and dark themes and its text stays readable. Empty value and error labels are hidden and take no space; field errors appear under their row.

A one-value Literal (schema const, not nullable) has nothing to choose or compute: its row shows the value as frameless read-only text, without a dropdown or Expression action. Fields the schema marks hidden have no row: Display(hidden=True) fields and one-value structural tags outside a union, such as a standalone LinRange's kind. Their input stays in state, and their errors go to the nearest drawn ancestor row or the form-wide error label. A float with schema decimals shows Direct and resolved values rounded to that many digits with trailing zeros trimmed; typed text with more digits stays as typed and the state keeps every digit. Section titles come from the schema.

Rows sit close together and nested groups use small margins. The labels of one model level share a left-aligned column as wide as its widest label, so that level's controls start at one left edge; each nested group has its own column. The editor has no outer margins; hosts add them.

Fields the schema marks `x-form-group` sit in a foldable group block (`form.group.<path>.<group>`, `form.group.<group>` at the root) of their model level. A level shows its ungrouped rows first, then its group blocks in the order of each group's first field; a group whose fields are all hidden has no block. The group title joins the level's label column and the block's rows get their own column, like a nested model. Groups start folded and model rows follow Display collapsed. The editor remembers the folds the user sets on groups and model rows by path, so a rebuild after an option or activation change keeps them. A folded group does not unfold for errors; its header shows a "Contains errors" note while any of its rows shows one. One stretch below the last row takes spare height, so nested groups do not grow.

set_editing_enabled(enabled=False) makes the form read-only but readable, for hosts that must not let the user change input, such as the workflows host during a run. No control is disabled, so nothing turns grey. Text fields are read-only QLineEdits: their text can be selected and copied, and their right-click menu keeps only the copying items, with the Expression action disabled. Dropdowns and checkboxes keep showing their value in normal colours but ignore clicks, wheel turns and keys other than Tab. A wheel turn over them scrolls the enclosing scroll area. Option command actions stay listed but disabled. Group and model folds still expand and collapse. External state publications still show. enabled=True restores every edit and the mode switch.

The workflows host's WorkflowFormPanel (`gui/app/workflows/panel.py`) passes neither `write` nor `run_command`; the measure Run panel passes the tab resource's `write` and `run_command`. Apply, Discard, Start, revision checks and persistence stay with the host. This tool does not migrate CfgSchema.
