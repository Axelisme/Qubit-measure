# gui/app/workflows — Workflow run and form ownership

**Last updated:** 2026-10-09，固定 Controller、唯一 Host 與同-token continuation seed

WorkflowController stays fixed for its Window's lifetime. Each Start supplies EnginePorts and a pending TunablesHost. One private run state concentrates the binding, native acceptance, token, producer phase and retained Runner settlement. Replacement waits for terminal cleanup. Native Engine status and artifacts remain authoritative; the operation token is only a receipt.

TunablesHost owns one run's unique FormState, fixed evaluation capture and submitted expression input before native acceptance. Attaching Engine does not replace draft or base. Pending Apply rejects before draft writes. Controller.apply_tunables is the declared common GUI/RPC submission entry; its body is still a seed. Host submits complete ordinary values; Engine owns numeric validation, revision, step capture and journal publication. Invalid form input retains draft. Only successful publication accepts input/base. No holder enforcement or GUI revision guard is introduced.

Pause retains the original operation, local RUN lease, progress and run inputs after owner delivery. Resume calls Runner.continue_operation with the same token and settlement, without another begin or init. The Runner continuation body is still a seed. Terminal delivery settles the native outcome and releases admission/resources before notifying the view; view errors are logged without changing native outcome. SessionDevices borrows shared public drivers. Hardware setup and limits remain with their existing owners.

Concrete T1WorkflowWindow and T1TuningPanel stay in zcu_lab. Window supplies per-Start resources and the fixed capture. Tuning presents the Controller-owned Host directly. RPC uses the same Window controls and shared transport. Start accepts optional leaf batches against current captured defaults; tunables edits submit the current shared draft, not Start defaults. Start and Resume call the declared synchronous live capture of every connected device; that DeviceService body is still a seed. Cached capture retains its separate public semantics.

The shared public/caller seed does not establish complete workflow behavior. Runner ordering/continuation, Controller tunables submission and device live capture still require implementation and acceptance. Records/PNG RPC, independent app composition, MCP, reload and CP remain incomplete. Offline evidence does not authorize hardware use or establish full F5/P2 acceptance.
