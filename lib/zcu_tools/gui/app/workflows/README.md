# gui/app/workflows — Workflow run and form ownership

**Last updated:** 2026-10-12，run/forms 與獨立 conversion 工具分離

WorkflowController stays fixed for its Window's lifetime. Each Start supplies EnginePorts and a pending TunablesHost. One private run state concentrates the binding, native acceptance, token, producer phase and retained Runner settlement. Replacement waits for terminal cleanup. Native Engine status and artifacts remain authoritative; the operation token is only a receipt.

TunablesHost owns one run's unique FormState, fixed evaluation capture and submitted expression input before native acceptance. Attaching Engine does not replace draft or base. Pending Apply rejects before draft writes. Controller.apply_tunables is the common GUI/RPC submission entry. Target and pending checks precede draft writes. Host submits complete ordinary values; Engine owns numeric validation, revision, step capture and journal publication. Invalid form input retains draft. Only successful publication accepts input/base. No holder enforcement or GUI revision guard is introduced.

Pause retains the original operation, local RUN lease, progress and run inputs after owner delivery. Resume calls Runner.continue_operation with the same token and settlement, without another begin or init. Stop during Resume submission retains ownership until continuation delivery without restarting the stopped native run. Terminal delivery settles the native outcome and releases admission/resources before notifying the view; view errors are logged without changing native outcome. Controller retains the original native control error across producer delivery or Resume admission unwind. Native failed reason takes priority over delivery errors. Idle paused failure finishes immediately; producing and resuming phases retain ownership until delivery or admission unwind. SessionDevices borrows shared public drivers. Hardware setup and limits remain with their existing owners.

Concrete T1WorkflowWindow and T1TuningPanel stay in zcu_lab. Window supplies per-Start resources and the fixed capture. Tuning presents the Controller-owned Host directly. RPC uses the same Window controls and shared transport. Start accepts optional leaf batches against current captured defaults; tunables edits submit the current shared draft, not Start defaults. Start forms use DeviceService's public detached native cached mapping without driver I/O. Resume takes only the run target and does not capture devices. Actual device evidence is captured by DevicePort before each env.run callback in the worker, under the retained RUN lease. SessionDevices live-reads detached BaseDeviceInfo subclasses through the public connected-driver mapping. Full setup revalidates dumped fields with the selected driver's info_model before driver I/O and forwards the original StopSignal.event. It does not interpret units, clamp, retry or update GUI State. Its capture_snapshot reuses the native acquisition helper; getter and per-env.run capture serve different purposes.

The independent workflows app is connected through the shared GUI runtime. Its Window borrows runner and progress from the same SessionServices and retains optional Qt parent embedding. The user-owned app injects zcu_lab.ALIAS_PRESET through build_session_services' generic alias_rows parameter. Session owns the editable table; preset import does not load the experiment catalog. Prepare forms uses read_context() for a fixed alias capture, without declaring roles or checking kind.

Saved run conversion belongs to independent Coherence/MIST tools in zcu_lab. Controller owns run controls and forms, without export bindings, admission, ledger or conversion helpers. GUI/RPC/MCP do not expose export commands. Removing those commands does not change native run lifecycle, records, plots or device capture.



Concrete records/PNG RPC and MCP forwarding are connected. The same Window exposes form schema/read and call-local batch preview without a persistent editing state. Shared FormState resolves explicit string expression envelopes with the public evaluator; ordinary strings remain literal and structural selectors remain ordinary typed tags. Coherence's new flux_dev default is a direct literal resolved once from the fixed alias capture. Missing capture or unbound alias retains the expression error input for public Invalid diagnostics. Other forms and valid saved input retain their existing defaults. Focused GUI/MCP form seams, fixed RunSnapshot and native subsequent Save have passed. Later alias edits and Save do not re-evaluate that snapshot. This evidence does not cover scenario 14 or full integration. Concrete app input persistence and source reload live in zcu_lab.workflows.gui. They reuse shared caretaker/FormState and the bounded SourceCatalogLoader; this framework Controller stays fixed. Reload can replace current form/science attachments after terminal delivery, while the Controller's retained run binding stays fixed. Base 09 final validation, complete integration gates and user CP-B acceptance remain separate requirements. These connections do not authorize hardware use.
